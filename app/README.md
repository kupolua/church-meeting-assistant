# CMA — мобільний застосунок (Flutter)

Екрани з `design/screens/*.html`, перенесені в Flutter 23.10.2026, плюс два нові
після зустрічі з партнером: підпис протоколу біометрією і «Стан справ».
Поки що все на вигаданих даних (`lib/mock_data.dart`) — так само, як і макети:
жодного справжнього імені чи зустрічі тут не має бути.

    lib/main.dart            чотири вкладки: Головна · Запис · Зустрічі · Пошук
    lib/theme.dart           кольори й шрифт (Onest) з макетів, в одному місці
    lib/widgets.dart         картка, ярлик розділу, пігулка статусу, таймкод
    lib/screens/             по файлу на екран; sign_sheet.dart — підпис через local_auth
    android/                 MainActivity = FlutterFragmentActivity (потрібно для біометрії)

## Запустити

    brew install --cask flutter            # один раз
    cd app && flutter pub get
    flutter run                            # на підключеному телефоні або емуляторі
    ./build_apk.sh                         # release → <repo>/CMA_app/cma-app-<version>.apk
    ./build_apk.sh http://10.0.2.2:8010    # …-dev.apk проти локального сервера

Версія береться з `pubspec.yaml` (`version: 0.1.0+1`): підніміть її там перед
збіркою, і файл назветься сам. Зараз 0.1.x — етап входу; 0.2 — запрошення й ключ
пристрою; 0.3 — читання даних.

Телефон: увімкнути «Налагодження через USB», підключити кабелем, `flutter devices`
має його показати. Емулятор: `~/Library/Android/sdk/emulator/emulator -avd Medium_Phone_API_35`.

## Вхід (крок 1 підключення до сервера, 23.10.2026)

До входу працює лише вкладка «Головна»: створити церкву або увійти за кодом із
пошти. Церква, створена із застосунку, чекає схвалення власника в панелі
`/platform`; до того застосунок показує «Запит розглядається». Токен живе в
захищеному сховищі телефона рік; на сервері це рядок `web_sessions` з
`client = 'app'`, тож його видно й можна відкликати на сторінці сесій.

    # сервер локально (порт 8010, база cma-dev-postgres на 5434)
    source ~/.claude/jobs/<job>/tmp/dev.env && uv run uvicorn church_assistant.web.main:app --port 8010
    # застосунок на емуляторі → цей Mac
    flutter run --dart-define=CMA_API=http://10.0.2.2:8010
    # показати вигадані дані на екранах (для перегляду дизайну)
    flutter run --dart-define=CMA_MOCK=true

Без SMTP на сервері код друкується в його журнал (`[api] code for …`).

## Шестерня (крок 2, 23.10.2026)

За іконкою налаштувань на «Головній»: профіль, «Учасники ради» (адміністратор
додає людину за поштою — їй іде лист, вхід далі звичайний, за кодом), «Ключ
підпису» цього телефона і «Вийти». Ключ Ed25519 створюється на телефоні (`lib/signing.dart`): де є відбиток чи
обличчя — за ними; де біометрії немає — під паролем підпису, яким запечатується
закрита половина (PBKDF2 → AES-GCM) і який вводиться при кожному підписі. На
сервер іде лише відкрита половина (`signing_keys`, міграція 022). Кнопка
«Перевірити підпис» проганяє захист без протоколу. Вимкнення учасника
відкликає його сесії і ключі.

## Читання (крок 3, 23.10.2026)

«Головна», «Зустрічі», протокол із темами й стенограмою, «Запис» (список
файлів) і «Пошук» беруть дані з `/api/v1/home|meetings|meetings/{date}|search`
(`web/routes/api_read.py`) — ті самі джерела, що й веб: теки зустрічей і
таблиці протоколів. Аудіо грає `just_audio` з `/meetings/{date}/audio` (HTTP
Range; заголовок із токеном іде через локальний проксі плагіна, тому
127.0.0.1 дозволений у network_security_config). Тап по таймкоду перемотує.
Вигаданих даних більше немає, крім «Стану справ» (крок 4).

## Підпис і «Стан справ» (крок 4, 24.10.2026)

Протокол на підписі (`review`) підписується з телефона: сервер віддає
`content_hash` — SHA-256 канонічного тексту протоколу
(`shared/protocol_hash.py`), телефон підписує ці 32 байти ключем Ed25519 за
відбитком або паролем підпису, сервер перевіряє підпис ключем із `signing_keys`
і лише тоді зберігає (`protocol_signatures`, міграція 023). Обовʼязкові підписанти
— члени ради, чиє імʼя збігається з присутнім у протоколі; коли всі вони
підписали поточний текст, протокол затверджується сам. Ведучий або
адміністратор може надіслати чернетку на підпис і затвердити вручну. Правка
тексту після підпису робить підпис застарілим (hash інший), не видаляє його.

Затвердження (з телефона або з сайту) перетворює кожне «Постановили» на
доручення в `tasks` — це і є «Стан справ»: нова → в роботі → виконано,
з нотаткою і посиланням на протокол.

## Звірка голосів (24.10.2026)

Задача, що зупинилась на `awaiting_review`, видна на «Головній» в «Обробці»
як «звірити голоси» (і в списках зустрічей/записів). Екран
`screens/speaker_review.dart` бере `/api/v1/meetings/{date}/speakers`: голоси
з часом мовлення, прапорцем упізнавання, таймкодами «послухати» (перемотують
плеєр) і полем імені з підказками (профілі голосів + учасники ради).
Збереження продовжує конвеєр (`queued_analysis`) або, для вже обробленої
зустрічі (іконка голосів у шапці зустрічі), ставить її на перезбирання.
Додавання голосу, якого діаризація не почула, лишається на сайті.

## Ведення протоколу (крок 5, 24.10.2026)

Адмін відкриває зустріч плюсом на «Зустрічах» (дата, ведучий, секретар) або кнопкою
«Відкрити протокол» на зустрічі із записом, але без протоколу. Ведучий цієї зустрічі
(і лише він, як і на сайті) бачить «Вести протокол»: `screens/draft.dart` — шапка
(секретар, кворум, присутні з галочками по раді, `GET /council`) і порядок денний;
`screens/item_editor.dart` — Слухали, Вирішили, голосування (три числа або жодного),
«не дійшли», Постановили, порядок і видалення. Текст зберігається кнопкою і при виході
назад; кожен запис API повертає протокол, яким він тепер є на сервері
(`web/routes/api_minutes.py`). «Надіслати на підпис» — внизу чернетки. Затверджений
протокол сервер не змінює (тригер 018) — застосунок показує його лише для читання.

## Що ще не підключено

- Запис у фоні зі шматками по 10 хвилин і завантаження файлу.
- Призначення доручення конкретному акаунту (зараз відповідальний — текст із протоколу).
- Додавання пропущеного голосу за часовим вікном (є на сайті).
- Запис у фоні з надсиланням 10-хвилинними шматками (`screens/record.dart` зараз лише рахує час).
- Підпис: біометрія працює, але підпис ще не ключем пристрою і нікуди не надсилається.
- «Стан справ»: таблиці задач і підписів у базі (міграції) ще не написані.
